CAMS writes and camera/USB-port notifications\n\n### 5.1 Does any AML code WRITE `CAMS`?\n\n**No.** Greps for write forms (`CAMS =`, `CAMS[`, `Store(..., CAMS)`, `CAMS)`-assignment) over every\n`*.dsl` return **no matches**. `CAMS` is only ever *read* (`DSDT.dsl:6744`, `DSDT.dsl:6830`) and declared\nas an 8-bit field (`DSDT.dsl:13826`). It therefore is a firmware/EC-owned byte in the LFCN shared-memory\nwindow at `0xCCF7D333` that AML consumes but never mutates. `[INFERENCE]` the EC/firmware updates it when\nthe physical privacy shutter toggles; nothing in the ACPI tables demonstrates a *software* path to set it.\n\n### 5.2 Any `Notify` targeted at camera / USB-port devices?\n\n**No `Notify` targets `CAMA` or `HSP3`/`HSP2`.** The complete `Notify` inventory of DSDT (grep) notifies\nonly: `GPP0/GPP1/GPP5/GP17/GP18` (`783-789`), `PWRB` (`790`), `PEGP`/`EDP0`/`LCD` (`797-811`, `14005-14026`),\n`XHC0`/`XHC1` (`817-818`), `NPCF` (`13965` etc.), `VPC0` (`14013` etc.), `LID0` (`14208`, `14223`),\n`ADP0`/`BAT0` (`14285-14287`), `GZFD` (16 sites, §4.6), `WMIU` (`14851`), and `^^^GPP0.PEGP` (`14457` etc.).\n\nThe only notifies on USB-related devices are:\n\n```asl\nDSDT.dsl:817   Notify (\\_SB.PCI0.GP17.XHC0, 0x02)   // Device Wake\nDSDT.dsl:818   Notify (\\_SB.PCI0.GP17.XHC1, 0x02)   // Device Wake\n```\n\nThese are generic `_L19` GPE device-wake notifications on the xHCI host controllers (the parents of the\nRHUB/HSP3/CAMA tree) — **not** camera-port notifications and not correlated with `_QDF`/0xD0.\n`[INFERENCE]` the camera switch is surfaced to software **only** through `_QDF`\'s\n`Notify (WMIU, 0xD0)` / `Notify (GZFD, 0xE8)` pair; there is no separate notify emitted on `CAMA`.\n\n---\n\n## 6.
